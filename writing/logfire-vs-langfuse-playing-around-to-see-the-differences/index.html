Logfire vs Langfuse: playing around to see the differences in LLM observability platforms

2026-11-14

The same small LLM pipeline traced in Langfuse and Logfire, seen as a developer, as an annotator, and as an analyst.

After hooktop, I wanted to see how the observability tools I borrowed ideas from feel in practice. So I built a small support ticket router and sent the same traces to Langfuse (self-hosted) and Logfire (free tier).

The router is a hybrid. A TF-IDF and logistic regression model labels each ticket. When it’s unsure, Claude Haiku 5.5 labels it instead. Cheap model first, LLM only when needed.

As a developer

Both tools are OpenTelemetry under the hood, and both read well. A plain span looks almost the same:

# Logfire
with logfire.span("route_ticket", input=ticket) as span:
    span.set_attribute("output", prediction)

# Langfuse
with langfuse.start_as_current_observation(name="route_ticket", as_type="span", input=ticket) as span:
    span.update(output=prediction)

The LLM connector is where they part ways. Logfire wraps the client:

logfire.configure()
client = Anthropic()
logfire.instrument_anthropic(client)  # add genai-prices for cost

Langfuse lets the Anthropic SDK’s own OpenTelemetry spans flow into it:

provider = TracerProvider()
langfuse = Langfuse(tracer_provider=provider)
client = Anthropic(open_telemetry={
    "tracer_provider": provider,
    "traces": {"enabled": True, "content_mode": "content"},
})

Logfire prices each call in the SDK and records prompts by default. Langfuse prices each call on the server from its own model table, splits tokens into input, output, cache and reasoning, and records prompts only after you ask for content.

As an annotator

This is where they differ most.

  • Langfuse gives you human annotation in the UI. I made a true_category score, queued 13 traces, and labeled them by hand after the run, without code. Many teams now skip the human step and let a classifier or an LLM-as-a-judge do the grading. Langfuse supports that too, with evaluators that score live traces and scores you send from code.
  • Logfire builds annotation around agents and online evaluation. You open an agent’s runs and give each one a pass, neutral or fail verdict. A custom label like true_category comes from code, with record_feedback.

Langfuse: the annotation queue after I labeled all 13 traces by hand.

The labels told the story. At a confidence threshold of 0.5, the router got 11 of 13 right. Both mistakes came from the cheap model, sure and wrong. At 0.7, it got 12 of 13.

Threshold Correct LLM calls Cost per run
0.5 11/13 4 $0.00029
0.7 12/13 12 $0.00086

One more right answer cost three times the LLM calls. That trade-off is why you label at all. Thirteen tickets are far too few to tune on, but enough to see the pattern.

A side note on my router: it is a pipeline, not an agent, so Logfire’s annotation page stayed empty. I copied my Langfuse labels over with record_feedback. They land as annotation records, which only SQL shows:

Logfire: the copied labels, found with SQL in the SQL Workbench.

To label a pipeline by hand in Logfire, you build a bit more yourself: a review page that reads the traces with the query API and sends each grade back with record_feedback. That is not too bad. Human review for pipelines is just not built in.

Does Langfuse sink to ClickHouse?

Yes, but not as an extra sink. ClickHouse is where Langfuse keeps every trace, observation and score. Postgres keeps users, projects, prompts and queues, and S3-compatible object storage keeps the raw events. Self-host it, and you already own a ClickHouse table of all your LLM calls:

SELECT name, count() AS calls, sum(total_cost) AS cost_usd
FROM events_core FINAL
WHERE name = 'anthropic.messages.create'
GROUP BY name

Getting your data out, side by side:

Setup How the data gets out
Langfuse self-hosted It’s already yours, in ClickHouse
Langfuse Cloud API, or a scheduled blob export (Pro with Teams, or Enterprise)
Logfire free tier Query API on your own schedule, or a second OpenTelemetry exporter. Data stays 30 days

These plans, limits and APIs are as of 2026-11-14. Both tools move fast, and the setup I used today may look different tomorrow. Check the pricing pages and feature pages before you plan around them.

Closing thoughts

Honestly, they’re almost the same tool: OpenTelemetry in, traces, tokens and costs out. Pick Langfuse when people who don’t write code grade the outputs. Pick Logfire when engineers own quality, and the whole service needs tracing, not only the LLM call.

If you already use Pydantic AI, Logfire comes from the same team, so the integration is one line:

logfire.configure()
logfire.instrument_pydantic_ai()

agent = Agent("anthropic:claude-haiku-5-5", output_type=TicketLabel)
agent.run_sync("I was charged twice")

Your agents then show up on Logfire’s Agents page with their runs and costs. Langfuse accepts Pydantic AI spans too:

langfuse = get_client()
Agent.instrument_all()

agent = Agent("anthropic:claude-haiku-5-5", output_type=TicketLabel)
agent.run_sync("I was charged twice")
langfuse.flush()

It’s about the same code, but in Logfire it just feels native.

My take: they are very similar. Choose the one that makes LLM evaluation and development more convenient for your own use case.
