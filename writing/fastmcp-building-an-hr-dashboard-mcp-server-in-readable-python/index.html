FastMCP: building an HR dashboard MCP server in readable Python

2026-11-17

A small FastMCP server for a fictional coffee company: HR tools, a dashboard, JWT auth and a payroll group that only HR can see, all in readable Python.

In this short write-up, I share my exploration of FastMCP, a Python framework for MCP servers maintained by Prefect. My example is an HR MCP server for Northfield Coffee, a fictional coffee bean company. It lets an MCP client such as Claude list employees, request PTO, show a dashboard and, for HR staff only, report salaries. The examples below show how little code each FastMCP feature needs.

I ran everything against fastmcp[apps]==4.2.0, and the full code with setup instructions is in the coffee-hr-mcp repo. The repo version is slightly refactored, so it differs a little from the snippets here.

An MCP server works like a librarian. It can reach the books, which here are the HR data. It checks who is asking before it helps. And it handles classified requests: every visitor picks from a known list.

Tools

A tool is one of those classified requests at the desk: the model asks, and the server does the work. In FastMCP, a tool is a Python function with a decorator:

from typing import Annotated

from fastmcp import Context, FastMCP
from pydantic import Field

mcp = FastMCP("Northfield Coffee HR")


@mcp.tool
def list_employees(department: str | None = None) -> list[dict]:
    """List employees, optionally filtered by department. Salaries are omitted."""
    return [
        e.model_dump(exclude={"salary"})
        for e in EMPLOYEES
        if department is None or e.department == department
    ]


@mcp.tool
async def request_pto(
    employee_id: Annotated[int, Field(gt=0)],
    days: Annotated[int, Field(ge=1, le=30)],
    ctx: Context,
) -> str:
    """Request PTO for an employee."""
    employee = get_employee(employee_id)
    if days > employee.pto_days_left:
        return f"Denied: {employee.name} only has {employee.pto_days_left} days left."
    employee.pto_days_left -= days
    await ctx.info(f"PTO approved for {employee.name}")
    return f"Approved: {days} days for {employee.name}."

EMPLOYEES is a list of Pydantic models, and get_employee() looks up one employee by ID. The snippet shows four things that FastMCP does for you:

  • Schema: FastMCP turns the type hints into a JSON schema and uses the docstring as the description. The model knows what each tool does and which fields to fill in.
  • Validation: FastMCP checks Field(ge=1, le=30) before the function runs, so a request for 45 days never reaches it.
  • Logging: ctx.info() sends a log message to the client while the tool runs.
  • Errors: get_employee() raises a ToolError for an unknown ID. The client gets a clear tool error, not a crash.

Resources and prompts

MCP has two more building blocks, with the same decorator style:

  • A resource is like the reference shelf: the client reads it as context, but cannot change it.
  • A prompt is like a request form with blanks: the user picks one, usually as a slash command, and fills it in.
@mcp.resource("hr://policies/pto")
def pto_policy() -> str:
    """The company PTO policy."""
    return (
        "Employees get 25 PTO days per year. "
        "Requests longer than 10 consecutive days need manager approval."
    )


@mcp.resource("hr://employees/{employee_id}")
def employee_profile(employee_id: int) -> dict:
    """Public profile for one employee."""
    return get_employee(employee_id).model_dump(exclude={"salary"})


@mcp.prompt
def onboarding_checklist(name: str, department: str) -> str:
    """Prompt template for a new starter's first-week checklist."""
    return f"Draft a first-week onboarding checklist for {name}, joining {department}."

The PTO policy is one fixed resource. The employee profile is a resource template, like a card catalogue with one card per employee: FastMCP passes {employee_id} from the URI to the function. The sample employees are numbered in list order, and Hamza Simon is second, so reading hr://employees/2 returns his profile, without the salary:

hr://employees/2 -> {"id": 2, "name": "Hamza Simon", "department": "Roastery", "title": "Roast Profiler", "pto_days_left": 3}

The prompt’s arguments, name and department, are the blanks on the form.

Dashboard

So far, every answer was text. A dashboard shows the same data at a glance. With MCP Apps, a tool can return a user interface that the client draws inside the conversation. FastMCP supports it through Prefab, a library of UI components that you write in Python:

from collections import Counter

from prefab_ui.components import Column, DataTable, DataTableColumn, Grid, Heading, Metric
from prefab_ui.components.charts import BarChart, ChartSeries


@mcp.tool(app=True)
def hr_dashboard() -> Column:
    """Show headcount metrics, headcount by department and the staff directory."""
    by_dept = Counter(e.department for e in EMPLOYEES)
    columns = [
        ("name", "Name"),
        ("department", "Department"),
        ("title", "Title"),
        ("pto_days_left", "PTO left"),
    ]
    with Column(gap=4) as view:
        Heading("Northfield Coffee - People dashboard")
        with Grid(columns=3):
            Metric(label="Headcount", value=len(EMPLOYEES))
            Metric(label="Departments", value=len(by_dept))
            Metric(
                label="Low on PTO (<5 days)",
                value=sum(e.pto_days_left < 5 for e in EMPLOYEES),
            )
        BarChart(
            data=[{"department": d, "headcount": n} for d, n in by_dept.items()],
            series=[ChartSeries(data_key="headcount", label="Headcount")],
            x_axis="department",
        )
        DataTable(
            columns=[DataTableColumn(key=k, header=h, sortable=True) for k, h in columns],
            rows=[e.model_dump(exclude={"salary"}) for e in EMPLOYEES],
            search=True,
        )
    return view

app=True tells FastMCP that this tool returns a UI. Each with block nests components, as HTML tags nest: a column holds a heading, a grid of three metrics, a bar chart and a table. There is no HTML, CSS or JavaScript to write.

A client that supports MCP Apps draws the metrics, the chart and a table that you can search and sort. Here is the dashboard in Claude Desktop, after one question:

Authentication

A JWT (JSON Web Token) works like a library card: it says who you are, when it expires and which rooms (scopes) you can enter. The server checks it on every request, against the company identity provider when JWKS_URI is set, or local test keys otherwise:

import os

from fastmcp import FastMCP
from fastmcp.server.auth.providers.jwt import JWTVerifier, RSAKeyPair

ISSUER = os.getenv("JWT_ISSUER", "https://idp.example.com")
AUDIENCE = "hr-mcp"

dev_keys: RSAKeyPair | None = None
if jwks_uri := os.getenv("JWKS_URI"):
    auth = JWTVerifier(jwks_uri=jwks_uri, issuer=ISSUER, audience=AUDIENCE)
else:
    dev_keys = RSAKeyPair.generate()
    auth = JWTVerifier(public_key=dev_keys.public_key, issuer=ISSUER, audience=AUDIENCE)

mcp = FastMCP("Northfield Coffee HR", auth=auth)

For local tests, dev_keys.create_token(...) issues test tokens. In production, you can swap JWTVerifier for a built-in provider such as Google, Microsoft Entra or Auth0. Either way, each request carries its own identity, unlike a shared static token.

Namespaces and tool groups

In FastMCP, related tools can live in their own small server, mounted on the main one under a namespace. Each group can have its own middleware, a natural place for an access rule. Here, payroll requires the hr:comp:read scope:

from fastmcp.server.auth import require_scopes
from fastmcp.server.middleware import AuthMiddleware

payroll = FastMCP("Payroll", middleware=[AuthMiddleware(auth=require_scopes("hr:comp:read"))])


@payroll.tool
def salary_report(department: str) -> dict:
    """Average and total salary for a department."""
    ...


@payroll.tool
def employee_salary(employee_id: int) -> dict:
    """Salary for a single employee."""
    ...


mcp.mount(payroll, namespace="payroll")

The namespace becomes a prefix: payroll_salary_report and payroll_employee_salary. A staff token does not see these tools, like a staff-only archive that is not on the public floor plan. The repo’s demo_auth.py prints this:

hr     tools: ['list_employees', 'request_pto', 'hr_dashboard', 'payroll_salary_report', 'payroll_employee_salary']
staff  tools: ['list_employees', 'request_pto', 'hr_dashboard']

The model cannot call a tool it never sees, and a direct call fails with insufficient scope. For a single tool, @mcp.tool(auth=require_scopes(...)) does the same without a separate server.

Deployment

There is nothing MCP-specific to learn here. Over HTTP, a FastMCP server is a regular Python web app: mcp.http_app() returns a standard ASGI app. You deploy it like any other HTTP service, and clients connect to the /mcp path. For example, this container image from the repo installs the locked dependencies with uv, without the dev tools:

FROM python:3.13-slim
COPY --from=ghcr.io/astral-sh/uv:0.11.32 /uv /uvx /bin/

WORKDIR /app
ENV UV_COMPILE_BYTECODE=1 \
    UV_LINK_MODE=copy

# Install locked dependencies first so this layer is cached between code changes.
COPY pyproject.toml uv.lock ./
RUN uv sync --locked --no-dev

COPY server.py ./
EXPOSE 8000
CMD ["uv", "run", "--no-sync", "server.py"]

In production, set JWKS_URI and JWT_ISSUER. Without them, the server falls back to local test keys and prints valid tokens to its logs.

Why FastMCP

Python: schemas come from type hints, validation from Pydantic, and even the UI is Python. It fits uv and Ruff, and I found it more natural than the TypeScript option.

Readability: the full server, with the dashboard, auth and payroll group, is under 150 lines of code. Most features in this post are one decorator or one argument.

Extensibility and built-ins: middleware for logging, rate limiting and caching, from_openapi() and from_fastapi() to wrap an existing API, many built-in auth providers, a CLI and an in-memory test client.

Maintenance: the project releases often, so pin your versions.

What surprised me most is how little of the code is about MCP itself. The rest is plain Python that I would write anyway. The full code, with the two-token demo script, is in the repo.
