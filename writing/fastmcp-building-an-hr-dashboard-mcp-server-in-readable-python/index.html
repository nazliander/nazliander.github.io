FastMCP: building an HR dashboard MCP server in readable Python

2026-11-17

A small FastMCP server for a fictional coffee company: HR tools, a dashboard written in Python, JWT auth and a payroll group that only HR can see.

This post walks through a small MCP server built with FastMCP, a Python framework for MCP servers maintained by Prefect. The example is an internal HR server for a fictional coffee bean company, Northfield Coffee. It lets an MCP client such as Claude list employees, request PTO, show a dashboard and, for HR staff only, report salaries. The code was run against fastmcp[apps]==4.2.0, and setup instructions are in the repo README.

Tools

A tool is a Python function with a decorator:

from typing import Annotated

from fastmcp import Context, FastMCP
from pydantic import Field

mcp = FastMCP("Northfield Coffee HR")


@mcp.tool
def list_employees(department: str | None = None) -> list[dict]:
    """List employees, optionally filtered by department. Salaries are omitted."""
    return [
        e.model_dump(exclude={"salary"})
        for e in EMPLOYEES
        if department is None or e.department == department
    ]


@mcp.tool
async def request_pto(
    employee_id: Annotated[int, Field(gt=0)],
    days: Annotated[int, Field(ge=1, le=30)],
    ctx: Context,
) -> str:
    """Request PTO for an employee."""
    employee = get_employee(employee_id)
    if days > employee.pto_days_left:
        return f"Denied: {employee.name} only has {employee.pto_days_left} days left."
    employee.pto_days_left -= days
    await ctx.info(f"PTO approved for {employee.name}")
    return f"Approved: {days} days for {employee.name}."

EMPLOYEES is a list of Pydantic models, and get_employee() raises FastMCP’s ToolError for an unknown ID, which the client receives as a tool error. FastMCP builds the JSON schema from the type hints, uses the docstring as the description, and validates the Field constraints before the function runs. Context is injected and used here to log to the client.

Resources and prompts

Tools are actions the model decides to call. MCP has two other building blocks: resources, which are read-only data the client can attach as context, and prompts, which are templates the user picks, usually as slash commands. Both use the same decorator style:

@mcp.resource("hr://policies/pto")
def pto_policy() -> str:
    """The company PTO policy."""
    return (
        "Employees get 25 PTO days per year. "
        "Requests longer than 10 consecutive days need manager approval."
    )


@mcp.resource("hr://employees/{employee_id}")
def employee_profile(employee_id: int) -> dict:
    """Public profile for one employee."""
    return get_employee(employee_id).model_dump(exclude={"salary"})


@mcp.prompt
def onboarding_checklist(name: str, department: str) -> str:
    """Prompt template for a new starter's first-week checklist."""
    return f"Draft a first-week onboarding checklist for {name}, joining {department}."

The second resource is a template: {employee_id} in the URI is passed to the function, so reading hr://employees/2 returns Hamza Simon’s profile. The prompt’s arguments become the fields the user fills in when selecting it.

Dashboard

MCP Apps lets a tool return a UI for the client to render. FastMCP supports it through Prefab, a Python component library:

from collections import Counter

from prefab_ui.components import Column, DataTable, DataTableColumn, Grid, Heading, Metric
from prefab_ui.components.charts import BarChart, ChartSeries


@mcp.tool(app=True)
def hr_dashboard() -> Column:
    """Show headcount metrics, headcount by department and the staff directory."""
    by_dept = Counter(e.department for e in EMPLOYEES)
    columns = [
        ("name", "Name"),
        ("department", "Department"),
        ("title", "Title"),
        ("pto_days_left", "PTO left"),
    ]
    with Column(gap=4) as view:
        Heading("Northfield Coffee - People dashboard")
        with Grid(columns=3):
            Metric(label="Headcount", value=len(EMPLOYEES))
            Metric(label="Departments", value=len(by_dept))
            Metric(
                label="Low on PTO (<5 days)",
                value=sum(e.pto_days_left < 5 for e in EMPLOYEES),
            )
        BarChart(
            data=[{"department": d, "headcount": n} for d, n in by_dept.items()],
            series=[ChartSeries(data_key="headcount", label="Headcount")],
            x_axis="department",
        )
        DataTable(
            columns=[DataTableColumn(key=k, header=h, sortable=True) for k, h in columns],
            rows=[e.model_dump(exclude={"salary"}) for e in EMPLOYEES],
            search=True,
        )
    return view

Clients that support MCP Apps render the metrics, chart and searchable table. Other clients receive the structured data. uv run fastmcp dev apps server.py opens a local preview.

Authentication

The server requires a valid JWT on every request. It uses the company identity provider when JWKS_URI is set and generates local test keys otherwise:

import os

from fastmcp import FastMCP
from fastmcp.server.auth.providers.jwt import JWTVerifier, RSAKeyPair

ISSUER = os.getenv("JWT_ISSUER", "https://idp.example.com")
AUDIENCE = "hr-mcp"

dev_keys: RSAKeyPair | None = None
if jwks_uri := os.getenv("JWKS_URI"):
    auth = JWTVerifier(jwks_uri=jwks_uri, issuer=ISSUER, audience=AUDIENCE)
else:
    dev_keys = RSAKeyPair.generate()
    auth = JWTVerifier(public_key=dev_keys.public_key, issuer=ISSUER, audience=AUDIENCE)

mcp = FastMCP("Northfield Coffee HR", auth=auth)

Requests without a token are rejected, and dev_keys.create_token(...) issues test tokens locally. JWTVerifier can also be replaced by a built-in provider such as Google, Microsoft Entra or Auth0. For an internal tool, JWTs from the company identity provider are a better fit than a shared static token, because each request carries the caller’s identity, expiry and scopes.

Namespaces and tool groups

Related tools can live in their own FastMCP server and be mounted on the main one under a namespace. Each group can have its own middleware, which makes it a convenient place to put access rules. Here the salary tools form a payroll group that requires the hr:comp:read scope:

from fastmcp.server.auth import require_scopes
from fastmcp.server.middleware import AuthMiddleware

payroll = FastMCP("Payroll", middleware=[AuthMiddleware(auth=require_scopes("hr:comp:read"))])


@payroll.tool
def salary_report(department: str) -> dict:
    """Average and total salary for a department."""
    ...


@payroll.tool
def employee_salary(employee_id: int) -> dict:
    """Salary for a single employee."""
    ...


mcp.mount(payroll, namespace="payroll")

The mounted tools are exposed as payroll_salary_report and payroll_employee_salary. A token without the scope doesn’t see them, and calling one directly fails with insufficient scope:

hr     tools: ['list_employees', 'request_pto', 'hr_dashboard', 'payroll_salary_report', 'payroll_employee_salary']
staff  tools: ['list_employees', 'request_pto', 'hr_dashboard']

For a single tool, @mcp.tool(auth=require_scopes(...)) does the same without a separate server.

Deployment

For local clients, uv run fastmcp install claude-desktop server.py registers the server over stdio. For a shared internal server, run it over HTTP in a container. The image installs the locked dependencies with uv, without the dev tools:

FROM python:3.13-slim
COPY --from=ghcr.io/astral-sh/uv:0.11.32 /uv /uvx /bin/

WORKDIR /app
ENV UV_COMPILE_BYTECODE=1 \
    UV_LINK_MODE=copy

# Install locked dependencies first so this layer is cached between code changes.
COPY pyproject.toml uv.lock ./
RUN uv sync --locked --no-dev

COPY server.py ./
EXPOSE 8000
CMD ["uv", "run", "--no-sync", "server.py"]
services:
  hr-mcp:
    build: .
    ports:
      - "8000:8000"
    environment:
      JWKS_URI: https://idp.example.com/.well-known/jwks.json
      JWT_ISSUER: https://idp.example.com
    restart: unless-stopped

docker compose up serves the MCP endpoint at http://localhost:8000/mcp. The same image runs on any container platform.

Why FastMCP

Python: schemas come from type hints, validation from Pydantic, and the UI is also Python. It fits the usual Python tooling, such as uv and Ruff, and I found it more natural than the TypeScript option.

Readability: the full server, including the dashboard, auth and payroll group, is under 150 lines of code.

Extensibility: middleware for logging, rate limiting and caching, namespaced groups of tools with their own access rules, and custom auth checks.

Built-in features: from_openapi() and from_fastapi() generate a server from an existing API, and there are around fifteen auth providers, a CLI and an in-memory test client.

Maintenance: the project is maintained by Prefect and releases often, so pin your versions.
